How it fits together

One source of truth, five automatic outputs

PMs keep their projects up to date in Asana using one shared standard. An AI agent with four custom skills, Python scripts and scheduled jobs reads that live data and produces everything else.

Nobody copies status from one place to another, and leadership never has to open Asana to know where things stand.

The foundation

Every project speaks the same language

Before, each PM reported progress their own way. I defined one standard that every project in the portfolio uses: status, priority, program area, phase, owner and ETA.

Phase is never typed by hand. The system reads it from the project's section names, so it stays accurate as work moves forward.

Each project also links to its 2026 KPI in a Program Metrics tracker, with a monthly goal and actual, so reviews can show numbers next to status.

The AI part

Type one sentence, get the review document

"Generate the deep-dive doc for Mei." One document per PM, built from live data. AI writes only the narrative, following built-in writing rules: specific data points, plain active sentences, highlights ordered by importance.

Early warning · try the sliders

Serious risks surface on their own

PMs rate each risk from 1 to 5 for severity and likelihood. The system multiplies them.

Scores fall into four bands. High (10–15) and Extreme (16–25) risks are pulled into the review document as focus topics automatically, each with its own framing, so a green project can't hide a serious risk.

Intake & backlog · try it

Every request gets a record and an answer

The old intake form wasn't connected to anything, so requests had no visible status.

Now each request lands in a backlog with its requestor, team, priority and problem. The reviewer sets a decision: Pending, Accepted, Rejected or Needs More Info, and the requester is emailed automatically. No decision in 14 days triggers an SLA alert.

Every Monday · 9:30 AM

Leadership reviews the portfolio without opening Asana

Three sections. ① Every active project grouped by program area, with status, PM, due date, priority and task health: overdue (OD), no due date (NDue) and no owner (NAss). PMs with open issues are @mentioned.

② At Risk, Off Track and On Hold projects with no status update in 14 days, named with their PM. ③ New requests and any waiting too long for a decision.

A duplicate check stops it posting twice, and a completion marker confirms each run.

Mon–Fri · 9:30 AM

A morning summary of everything that changed

Each weekday at 9:30 the system checks every project for changes since yesterday's run (since Friday on Mondays) and posts seven kinds of alert: status updates, completions, due in 7 days, due today, overdue, new requests and backlog SLA breaches.

A token warm-up runs at 9:25 so the 9:30 run doesn't fail on login.

Primary and backup owners, a team guide, SOPs and a maintenance guide for next year's reset. A new owner can take over in under 30 minutes.

What I learned

A system is only as good as the data people put into it.

Getting PMs to update Asana consistently mattered more than any automation I built.
